# Plan: ให้ loop บริหารโควตา Claude/Codex เอง
Date: 2026-10-09

## Goal
ก่อนเริ่มทุกรอบ loop เช็คโควตาสดของทั้งสองตัว แล้วเลือก "ตัวนำ" (ทำงานหนัก/กิน token) กับ "ตัวช่วย" (รีวิว/ความเห็นที่สอง)
ทั้งสองตัวสลับบทกันได้ ถ้าเต็มทั้งคู่ให้รอจนตัวที่รีเซ็ตก่อนกลับมา

## Context (คำตอบผู้ใช้)
- ไม่มีรูปแบบตายตัว: ตัวที่โควตาเหลือเยอะทำงานกิน token ส่วนตัวที่เหลือน้อยช่วยรีวิว
- คิดเวลารีเซ็ตด้วย เช่น เหลือ 80% เท่ากัน แต่ตัวหนึ่งรีเซ็ต 5 ชม. ในอีก 20 นาที อีกตัวอีก 4 ชม. ให้ใช้ตัวที่รีเซ็ต 20 นาทีก่อน (ใช้ไม่ทันก็เสียเปล่า)
  แต่สุดท้ายต้องดูโควตารายสัปดาห์ประกอบ
- ให้สร้าง STOP แล้วแก้ทันที (loop รัน PID 3652, job `20261009-105614-s2anc_wide` กำลังเทรนใน WSL)

ข้อมูลสด:
- Codex: `codex app-server` → `account/rateLimits/read` ได้ค่าสด ไม่เสีย token (มี rateLimitResetCredits 3 ใบ: แสดงอย่างเดียว ไม่ใช้เอง)
- Claude: `claude -p --model haiku --max-turns 1 --tools ""` ได้ rate_limit_event ใช้ ~$0.0006/ครั้ง 1.4 วิ
  (log เดิมบอก 5 ชม. 7% แต่ค่าจริง 21% เพราะ session interactive ใช้โควตาร่วมกัน → ต้อง probe สด)

## Steps
1. `tools/quota.ps1`: ฟังก์ชันอ่านโควตาสด (fallback เป็น log) + คะแนน + ตัดสินใจ ตัวนำ/ตัวช่วย/รอ ใช้ได้ทั้ง dot-source และ `-Json`
   คะแนน = (headroom 5 ชม.) / (ชม. ที่เหลือถึงรีเซ็ต) × (ตัวคูณรายสัปดาห์ = สัดส่วนที่เหลือ / สัดส่วนเวลาที่เหลือ, จำกัด 0.25–2)
   ใช้ไม่ได้ถ้า 5 ชม. ≥ 90% หรือ สัปดาห์ ≥ 95%
2. `tools/claude.ps1`: ให้ Codex (ตอนเป็นตัวนำ) เรียก Claude เป็นตัวช่วย บันทึกลง `reports/claude-helper.md`
3. `codex.sh` / `claude.ps1`: เช็คโควตาก่อนเรียก ถ้าตัวช่วยใกล้เต็มให้ปฏิเสธพร้อมบอกให้ทำเอง
4. `run-loop.ps1`: ก่อนแต่ละรอบ เรียก quota → เลือกตัวนำ → ต่อท้าย prompt ด้วยสถานะโควตา → รัน `claude -p` หรือ `codex exec`
   ถ้าใช้ไม่ได้ทั้งคู่ → รอถึงเวลารีเซ็ตที่เร็วที่สุด (หยุดได้ด้วย STOP) และบันทึกตัวนำในรายงาน
5. `PROMPT.md`: เขียนให้ใช้ได้ทั้งสองตัว + กฎแบ่งงานตามโควตา
6. `credits.ps1`: ใช้ข้อมูลสดจาก quota.ps1 + แสดงตัวนำรอบหน้า + เครดิตรีเซ็ตของ Codex
7. README

## How it will be verified
- quota.ps1 -Json ได้ค่าตรงกับ probe; ทดสอบสูตรด้วยกรณีตัวอย่างของผู้ใช้ (80%/80%, 20 นาที vs 4 ชม.)
- run-loop.ps1 ผ่าน parser ของ PowerShell; ลองรันจริง 1 รอบด้วย `-MaxIterations 1` ถ้าผู้ใช้โอเค (ไม่งั้นให้ผู้ใช้เปิด loop เอง)
- codex.sh/claude.ps1 ปฏิเสธเมื่อบังคับ threshold ต่ำ

## Risks / assumptions
- Codex ตอนเป็นตัวนำรันบน Windows (PowerShell) `bash` ใน PATH อาจเป็น WSL bash → ให้ Codex เรียก Claude ผ่าน `pwsh` เท่านั้น
- เกณฑ์ 90%/95% และสูตรคะแนนเป็นค่าตั้งต้น ปรับได้ใน quota.ps1
- ไม่ใช้เครดิตรีเซ็ตฟรีของ Codex อัตโนมัติ (เป็นการตัดสินใจของผู้ใช้)
