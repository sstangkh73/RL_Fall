# การทบทวนงานวิจัยก่อนเริ่ม RL Fall

**วันที่ตรวจค้น: 10 กันยายน 2026**  
**คำตัดสิน: ควรทำการทดลองนำร่องแบบมีเงื่อนไข; ยังไม่ควรลงทุนสร้าง FEM ทั้งร่างกาย**

## 1. คำตอบต่อการตัดสินใจ

แนวคิด “ให้ AI เรียนรู้ล้มอย่างป้องกันตัว” มีงานรองรับมากแล้ว ตั้งแต่ตัวทำนายการล้ม การลดแรงกระแทก การเลือกส่วนร่างกายรับแรง ไปจนถึงตัวควบคุมเดียวที่ครอบคลุมการทรงตัว การล้ม และการลุกขึ้น การตั้งโครงการด้วยคำอ้างว่า “ยังไม่มีใครให้ policy เดียวค้นพบการสลับยืน–ล้ม” จึงไม่แข็งแรงพอ โดยเฉพาะเมื่อพิจารณา FIRM และงาน Embedding Classical Balance Control Principles ปี 2026. [FIRM](https://arxiv.org/html/2511.07407v1), [Embedding Classical Balance Control Principles](https://arxiv.org/html/2603.08619v1)

การจำลองความเค้น ความล้า และอายุใช้งานร่วมกับ RL ก็มีแล้ว งาน Prolonging Tool Life ใช้ FEA ประเมินความเสียหายเครื่องมือและนำอายุใช้งานเข้า reward โดยตรง จึงไม่ควรอ้างความใหม่เพียงว่า “ใช้ฟิสิกส์แทนคะแนนดาเมจที่ตั้งขึ้นเอง”. [Prolonging Tool Life](https://arxiv.org/html/2507.17275)

**คำถามที่ยังน่าตรวจเชิงทดลองคือ:** เมื่อการกระทำทำให้ร่างกายเสียหายอย่างคงอยู่ และความเสียหายนั้นลดความสามารถทำภารกิจในอนาคตจริง ๆ policy เดียวจะเรียนรู้การล้มเพื่อรักษาความสามารถนั้นได้แค่ไหน หากให้รางวัลเฉพาะภารกิจ โดยไม่มีโทษความเสียหาย รางวัลอายุยืน หรือคำสั่งให้เปลี่ยนโหมด?

ในการค้นครั้งนี้ยังไม่พบงานที่ตรวจคำถามดังกล่าวครบทั้งกลไกความเสียหายของร่างกาย การล้มแบบคาดการณ์ล่วงหน้า และการทดลองแยกเหตุของพฤติกรรมอย่างตรงกัน นี่เป็น **ช่องว่างที่มีเหตุผลให้ทดสอบ** ไม่ใช่หลักฐานยืนยันว่าเป็นงานแรกของโลก ความมั่นใจในข้อสรุปเชิงลบนี้อยู่ระดับปานกลาง เพราะถ้อยคำที่งานแต่ละสาขาใช้ต่างกัน และโค้ดบางโครงการยังไม่ได้ตรวจถึงระดับรันซ้ำ

คุณค่าที่ควรตั้งเป้าคือการอธิบายว่า **ผลเสียต่อความสามารถในอนาคตเพียงพอให้เกิดการป้องกันตัวเมื่อใด และไม่เพียงพอเมื่อใด** ไม่จำเป็นต้องเสนออัลกอริทึม RL ใหม่ แต่ต้องมีการทดลองที่แยกสาเหตุได้และแบบจำลองที่ตรวจสอบได้

## 2. ขอบเขตและความหมายที่ใช้

การทบทวนนี้ครอบคลุม safe falling, unified recovery, damage-aware RL, health-aware control, intrinsic motivation, self-preservation และ FEM/soft-body RL ใช้บทความต้นฉบับ เว็บไซต์ผู้เขียน แหล่งเผยแพร่วิชาการ และ repository เจ้าของงานเป็นหลัก อ่านวิธีการและ reward ของงานใกล้เคียง แยกจากงานที่ตรวจได้เพียงบทคัดย่อหรือข้อมูลโครงการ

นี่เป็นการทบทวนแบบมุ่งโจทย์และตามเอกสารอ้างอิง ไม่ใช่ systematic review ที่ลงทะเบียน protocol และครอบคลุมทุกฐานข้อมูล ไม่ใช้จำนวนผลค้นหาเป็นจำนวนงานวิจัย และไม่ใช้ข้อความ “first” ในบทนำของผู้เขียนเป็นข้อพิสูจน์ความใหม่โดยอัตโนมัติ ตารางหลักฐานแยกไว้ใน [evidence_matrix.md](./evidence_matrix.md)

ต้องแยกคำต่อไปนี้ก่อนเปรียบเทียบงาน:

| คำ | ความหมายสำหรับโครงการนี้ |
|---|---|
| ป้องกันการล้ม | ยังรักษาหรือกู้การทรงตัวได้ก่อนลงพื้น |
| ลดผลกระทบระหว่างล้ม | เปลี่ยนการเคลื่อนไหวก่อนหรือระหว่างกระแทกให้ผลเสียลดลง |
| ลุกหลังล้ม | กลับมาทำงานหลังลงพื้นแล้ว ไม่ได้พิสูจน์ว่าล้มปลอดภัย |
| policy เดียว | ตัวตัดสินใจการกระทำหนึ่งตัวขณะใช้งาน; ต้องตรวจต่อว่าการฝึกมี teacher, gate หรือ skill priors หรือไม่ |
| reward เดียว | ผลรวมเป็น scalar เดียวก็ยังอาจมีโทษความเสียหายหลายสิบพจน์ |
| ความเสียหายคงอยู่ | ความแข็งแรง การส่งแรง ช่วงการเคลื่อนไหว หรือการรับรู้เปลี่ยนไปและไม่รีเซ็ตทันที |
| การจัดลำดับความสำคัญที่เรียนรู้ | เปลี่ยนการรักษาส่วนร่างกายตามผลต่อภารกิจ โดยไม่ได้กำหนดน้ำหนักคุณค่าของแต่ละส่วนไว้ล่วงหน้า |
| ไม่มี pain penalty | ไม่มีคะแนนลบตรงจากความเสียหาย; ไม่ได้หมายความว่าไม่มี reward หรือไม่มีข้อมูลเกี่ยวกับร่างกาย |

“สัญชาตญาณ” ในรายงานหมายถึงพฤติกรรมป้องกันตัวที่ปรากฏจากการเรียนรู้ ไม่ใช่ข้ออ้างว่า agent รู้สึกเจ็บหรือมีประสบการณ์เหมือนมนุษย์

## 3. งานที่กระทบความใหม่โดยตรง

### 3.1 ตัวทำนายและสวิตช์ยืน–ล้ม: มีประวัติยาวนาน

**Learning to Predict Humanoid Fall — Kalyanakrishnan และ Goswami, 2011.** งานนี้ทำนายว่าตัวควบคุมสมดุลที่กำหนดจะกู้สถานการณ์ได้หรือไม่ เพื่อส่งต่อไปยังตัวควบคุมการล้ม และศึกษาความสัมพันธ์ของ false positives กับเวลาที่แจ้งล่วงหน้าอยู่แล้ว ข้อสังเกตที่ใช้กับโครงการใหม่คือ “กู้ไม่ได้” ในการทดลองสัมพันธ์กับความสามารถของ controller ที่ใช้ ไม่ใช่การพิสูจน์ว่าฟิสิกส์ไม่อนุญาตให้ยืนต่อภายใต้นโยบายใด ๆ. [บทความต้นฉบับ](https://www.cse.iitb.ac.in/~shivaram/papers/kg_ijhr_2011.pdf)

**SafeFall — 2025 preprint.** ใช้ GRU ทำนายการล้มและ policy ลดความเสียหายร่วมกับตัวควบคุมปกติ จัดน้ำหนักส่วนเปราะบางต่างกันอย่างชัดเจน: หัวและมือได้รับน้ำหนักสูงกว่าบางส่วนของลำตัวและขามาก จึงหักล้างสมมติฐานกว้างว่า RL ปัจจุบันถือความเสียหายทุกส่วนเท่ากัน อย่างไรก็ตาม วิธีนี้ยังสอนความสำคัญผ่าน reward ไม่ได้แสดงการค้นพบคุณค่าของอวัยวะจากการเสียความสามารถในอนาคตเพียงอย่างเดียว. [วิธีการ SafeFall](https://arxiv.org/html/2511.18509v1)

**Guardians as You Fall — 2023 preprint.** ใช้หลายโหมดและนโยบาย transition/recovery มีการออกแบบโหมดที่ยอมรับได้และ planner เลือกการเปลี่ยนผ่าน เป็น baseline ของสถาปัตยกรรมที่ออกแบบการสลับไว้ แต่ไม่ใช่ตัวแทนของงานทั้งหมดในสาขา. [บทความ](https://arxiv.org/html/2310.04828v1)

### 3.2 “Unified” มีหลายความหมาย และมีมาก่อนโจทย์นี้

**Learning a Unified Control Policy for Safe Falling — 2017.** ใช้ mixture of actor-critics ซึ่งแต่ละ expert เชื่อมกับส่วนที่จะสัมผัสพื้น และเลือกตามค่าที่ประเมินไว้ เป้าหมายลด impulse สูงสุด จึงเป็นการรวมการเลือกท่าล้มหลายแบบ แต่ไม่ใช่ monolithic policy ที่เรียนรู้วงจรทรงตัว–ล้ม–ทำภารกิจต่อจาก reward ภารกิจอย่างเดียว. [บทคัดย่อต้นฉบับ](https://arxiv.org/abs/1703.02905)

**Learning Arm-Assisted Fall Damage Reduction and Recovery for Legged Mobile Manipulators — 2023.** เรียนรู้การใช้แขนลดผลกระทบและฟื้นตัวใน controller เดียวสำหรับช่วงฉุกเฉิน แต่ระบบโดยรวมยังคาดว่าจะมี controller ภารกิจปกติส่งต่อให้ มี reward ความปลอดภัยและ reward ภารกิจที่เปลี่ยนตามเวลาระหว่างฝึก งานนี้เป็น predecessor สำคัญของการรวมลดแรงกับลุกกลับขึ้น. [§III–IV](https://arxiv.org/html/2303.05486v1)

**FRASA — 2024.** เป็น end-to-end fall recovery และ stand-up บนหุ่น Sigmaban มีการลดมิติด้วยความสมมาตรเหลือการควบคุมที่มีผลอิสระ 5 มิติ จึงเป็นหลักฐานว่าการย่อโจทย์ทำให้วิจัยบนเครื่องทั่วไปเป็นไปได้ แต่ reward เน้นเป้าท่ายืนและข้อกำกับอื่น ไม่ได้จำลองกระดูกหักแล้วให้ agent ค้นพบการรักษาความสามารถเอง. [บทความ](https://arxiv.org/html/2410.08655v1)

**FIRM — 2025 preprint.** รวม fall safety และ recovery จากตัวอย่างมนุษย์เพียงไม่กี่ชุด ใช้ RL สร้างทักษะ ขยายข้อมูล และ diffusion memory พร้อมการปรับตัวด้วย codebook จึงไม่ใช่รูปแบบ classifier + balance policy + fall policy ตามที่ตั้งสมมติฐานไว้เดิม แต่มีโครงสร้างการฝึกและตัวอย่างชี้นำพฤติกรรมชัดเจน. [วิธีการ FIRM](https://arxiv.org/html/2511.07407v1)

**VIGOR — 2026, ตรวจ v2.** ต่อขยายแนว unified fall safety ไปยังภูมิประเทศและการรับรู้ด้วยภาพ มี teacher–student และเป้าหมายจาก demonstrations พร้อม reward imitation/regularization การ deploy เป็น policy เดียวจึงไม่เท่ากับฝึกโดยไม่มีมนุษย์ระบุพฤติกรรมที่ต้องการ. [บทความ v2](https://arxiv.org/html/2602.16511v2)

### 3.3 งานที่ใกล้ “policy เดียวค้นพบยืน→ล้ม” มากที่สุด

**Embedding Classical Balance Control Principles in Reinforcement Learning for Humanoid Recovery — Poddar และคณะ, 9 มีนาคม 2026.**

บทความรายงาน policy เดียวบน Unitree H1-2 ที่ครอบคลุม ankle/hip stabilization, corrective stepping, compliant falling และ stand-up โดยไม่ใช้ reference trajectories หรือ scripted contact sequences จึงเป็นหลักฐานตรงที่ทำให้การอ้างความใหม่ด้วย single-policy transition เพียงอย่างเดียวอ่อนลงมาก

แต่ §III-E ใส่ capture-point/CoM/momentum shaping รวมถึง reward สนับสนุนมือและศอกตามความสูง โบนัสอยู่รอด และโทษจบ episode; §III-F ยังมี curriculum และ termination เมื่อเกิด contact อันตราย ดังนั้นนี่ไม่ใช่การทดลองที่ผลจากร่างกายเสียหายเป็นแรงจูงใจเพียงทางเดียว รายงานนี้ไม่ได้ตรวจทำซ้ำผล hardware และไม่ใช้คำว่า “compliant falling” เท่ากับพิสูจน์ลดการบาดเจ็บจริง. [บทความและ reward decomposition](https://arxiv.org/html/2603.08619v1)

**Unified Walking, Running, and Recovery for Humanoids via State-Dependent Adversarial Motion Priors — พฤษภาคม 2026.**

ใช้ actor เดียวขณะ deploy แต่มี threshold เลือก discriminator ระหว่างฝึก พร้อม reference motions และ fall cost งานนี้ทำให้ต้องแยก “ไม่มีสวิตช์ขณะใช้งาน” ออกจาก “ไม่มีมนุษย์กำหนดขอบเขตใด ๆ ระหว่างฝึก” เป็นคนละข้ออ้าง. [§III](https://arxiv.org/html/2605.18611v1)

### 3.4 มีการเทียบ single-policy กับ multi-policy แล้ว

**A Multi-policy Approach Based on Clustering for Minimizing the Damage on a Falling Ballbot — ฉบับไฟล์ CoDIT 2025 / ระเบียนมหาวิทยาลัย 2026.**

งานนี้เปรียบเทียบหลาย policy ตาม cluster ท่าแขนเริ่มต้นกับ policy เดียว ทั้งแบบมี/ไม่มี cluster ID และแนว curriculum จริง การเลือก expert ทำเมื่อเริ่มการล้มเพื่อใช้ตลอดช่วง ไม่ใช่การทำนายจุดที่ต้องเลิกทรงตัวใน controller ภารกิจปกติ ใช้ contact force และ joint yank เป็น cost และจบการทดลองเมื่อกระแทกหรือถึงเวลาจำกัด

จึงต้องแก้คำอ้างเดิมเป็น “ยังไม่พบการเทียบสถาปัตยกรรมภายใต้โจทย์ความเสียหายคงอยู่และผลต่อภารกิจต่อเนื่องแบบที่เสนอ” ไม่ใช่ “ยังไม่มีใครเทียบ single กับ multi”. [PDF ผู้จัดประชุม](https://www.codit2025-virtual-event.com/web/content/1251?download=true&unique=85e933f7d1b6fd18c5d94e5300d42d1d648cd09a), [ระเบียนมหาวิทยาลัย](https://iris.unitn.it/handle/11572/471750)

### 3.5 การค้นพบท่าป้องกันตัวโดยไม่เลียนแบบก็มีแล้ว

**Discovering Self-Protective Falling Policy for Humanoid Robot — ธันวาคม 2025.** เรียนรู้ท่าค้ำลักษณะสามเหลี่ยมจาก reward และ curriculum โดยไม่จำเป็นต้องให้ท่ามนุษย์เป็นเป้าหมาย แต่ยังลงโทษแรงในส่วนสำคัญและมีการสลับจาก walking ไป fall policy ในการทดลอง จึงเป็นหลักฐานว่าท่าที่ดู “ค้นพบเอง” เกิดขึ้นได้ภายใต้ objective ที่มนุษย์กำหนดไว้. [บทความ โดยเฉพาะ §V-E](https://arxiv.org/html/2512.01336v1)

**Robot Crash Course: Learning Soft and Stylized Falling — พฤศจิกายน 2025.** ฝึกการล้มให้ลดผลกระทบและมีท่าปลายทาง/รูปแบบที่ต้องการ มีการป้องกันส่วนสำคัญ งานนี้ยืนยันว่า “เรียนรู้ท่าล้มที่ดี” เป็นพื้นที่ที่มีการแข่งขันแล้ว แต่ไม่ได้ตอบว่าความเสียหายที่ลดผลตอบแทนภายหลังเพียงอย่างเดียวจะสอนให้ป้องกันตัวได้หรือไม่. [บทความ](https://arxiv.org/html/2511.10635v1)

## 4. งานที่ใกล้แนวคิด “มีร่างกายที่เสียหายได้ แล้วให้ agent เรียนรู้ใส่ใจ”

### 4.1 ความเค้นและอายุใช้งานร่วมกับ RL: ทำแล้ว

**Prolonging Tool Life — preprint เริ่มปี 2025; ตรวจฉบับปรับปรุงปัจจุบัน.** ใช้ประวัติแรงจากภารกิจไปทำ FEA ได้ประวัติความเค้น แล้วใช้ rainflow counting และกฎ Miner ประเมินความล้า/remaining useful life (RUL) นำ RUL เป็นรางวัลปลาย episode และกระจายสัญญาณย้อนกลับไปช่วยเรียนรู้ มีการทดลองเครื่องมือจริงด้วย

จุดต่างสำคัญคืออายุใช้งานถูกให้คุณค่าโดยตรงใน objective นี่เป็นหลักฐานที่ใกล้และควรใช้เป็นฐานวิธีประเมินวัสดุ แต่ยังไม่ตอบเงื่อนไข “ให้เห็นเพียงผลที่ใช้งานต่อได้แย่ลง”. [§III-B, §IV-B, Eq.10–16](https://arxiv.org/html/2507.17275)

**Evolving Afferent Architectures: Biologically-inspired Models for Damage-Avoidance Learning — กุมภาพันธ์ 2026.** ใช้แบบจำลองเข่าและความเสียหายสะสมร่วมกับระบบ afferent ที่วิวัฒน์ผ่าน outer loop ส่วน policy เรียนรู้ผ่าน PPO

[สมการและข้อจำกัด](https://arxiv.org/html/2602.04807v1)

### 4.3 damage-aware simulator ไม่จำเป็นต้องเท่ากับร่างกายเสียหน้าที่

**OopsieVerse — มิถุนายน 2026.** สร้าง benchmark การจัดการวัตถุพร้อมความเสียหายเชิงกล ความร้อน และของเหลว ในส่วน RL ใส่ damage penalty โดยตรง งานนี้มีประโยชน์เป็นแนวทางตัวชี้วัดความปลอดภัย แต่จากส่วนวิธีที่ตรวจ ยังไม่เพียงพอจะยืนยันว่าทดสอบสายเหตุ “ร่างกายของ agent เสียหาย → สูญเสียหน้าที่อย่างถาวร → ผลตอบแทนภารกิจต่อเนื่องลดลง” แบบที่เสนอ. [บทความ โดยเฉพาะส่วน RL](https://arxiv.org/html/2606.31993v1)

**A Reinforcement Learning Approach to Health Aware Control Strategy — MED 2019 / arXiv 2020.** ศึกษา controller ที่คำนึงถึงความเสื่อมและ RUL ของระบบมอเตอร์ เป็น prior art ที่ต้องยอมรับสำหรับ health-aware control แต่หลักฐานที่ใช้ในรายงานนี้อยู่ระดับบทคัดย่อและ formulation ที่สรุปไว้ ไม่ใช้ยืนยันรายละเอียด simulator ภายใน. [ต้นฉบับ arXiv](https://arxiv.org/abs/2010.09269)

### 4.4 รับมือกับร่างกายเสียแล้ว ต่างจากเรียนรู้หลีกเลี่ยงการทำให้เสีย

**Reset-free Trial-and-Error Learning for Robot Damage Recovery — 2016 preprint.** เน้นเรียนรู้ชดเชยหลังร่างกายถูกทำให้เสียหาย โดยอาศัยประสบการณ์/พฤติกรรมจากโมเดลปกติและการทดลองต่อเนื่อง มีความเกี่ยวข้องกับผลด้าน functionality แต่การปรับตัวหลัง damage ที่ถูกใส่มาจากภายนอกไม่ใช่หลักฐานของการป้องกัน damage ที่การกระทำของ agent กำลังจะก่อ. [บทคัดย่อ](https://arxiv.org/abs/1610.04213)

แนวเดียวกันปรากฏใน **Light REACT** ซึ่งหน้าเทคนิคของผู้พัฒนารายงาน recovery/locomotion/crawling เมื่อ actuator ใช้ไม่ได้หรือข้อต่อถูกจำกัด ผ่านหลาย teachers การ distillation และการฝึก reward ให้ชอบท่ายืน แหล่งนี้ตรวจได้จากเนื้อหาที่ดัชนีเว็บแสดงของเว็บไซต์ผู้พัฒนา แต่เปิดหน้าเต็มไม่สำเร็จ จึงจัดเป็นข้อมูลโครงการอุตสาหกรรมเพิ่มเติม ไม่ยกระดับเป็นงาน peer-reviewed หรือหลักฐานว่ามี endogenous damage prevention แล้ว. [หน้าเทคนิค Light REACT](https://www.lightorigins.com/en/blog/light-react)

### 4.5 การเกิดพฤติกรรมอยู่รอดเอง: แนวคิดไม่ใหม่ แต่ไม่ใช่ผลลัพธ์ที่รับประกัน

**SMiRL — preprint 2019, ICLR 2021.** แสดงการทรงตัวและหลีกเลี่ยงอันตรายในบาง environment โดยใช้ intrinsic reward ลด surprise ไม่ใช้ task-specific reward แบบปกติ แต่ยังมี objective ที่ตั้งไว้ชัดเจน จึงไม่ใช่ “ไม่มี reward” และไม่ใช่ “ภารกิจภายนอกอย่างเดียว”

ภาคผนวก Doom ต้องปรับ environment เพื่อหลีกเลี่ยงการจบชีวิตที่ย้อนกลับไปสภาพเริ่มต้นอันคาดเดาได้ง่าย ข้อนี้เตือนโดยตรงว่า reset และ termination สามารถเปลี่ยนแรงจูงใจจนตรงข้ามกับการรักษาตัวเอง. [SMiRL รวมภาคผนวก](https://arxiv.org/pdf/1912.05510)

**Empowerment As Replacement for the Three Laws of Robotics — 2017.** ใช้การรักษาความสามารถควบคุมอนาคตเป็น intrinsic objective ที่สัมพันธ์กับการป้องกันตัวเอง แต่ยังเป็น objective ที่เลือกไว้ ไม่ใช่หลักฐานการล้มของ humanoid จาก damage dynamics อย่างเดียว. [บทความต้นฉบับ](https://www.frontiersin.org/journals/robotics-and-ai/articles/10.3389/frobt.2017.00025/full)

**Optimal Policies Tend To Seek Power — NeurIPS 2021.** ให้ผลเชิงทฤษฎีเกี่ยวกับแนวโน้มรักษาทางเลือกภายใต้เงื่อนไขของ MDP และการกระจาย reward รวมถึงสถานการณ์ที่ agent ถูกทำลายได้ ผลนี้รองรับเหตุผลเชิงเครื่องมือของการรักษาความสามารถ แต่ไม่ได้รับประกันว่า PPO ที่มีข้อมูลจำกัดจะค้นพบการม้วนตัวก่อนตกพื้น. [บทความ NeurIPS](https://proceedings.neurips.cc/paper/2021/file/c26820b8a4c1b3c2aa868d6d57e14a79-Paper.pdf)

**The Contingencies of Physical Embodiment Allow for Open-Endedness and Care — 2025.** เชื่อมความเปราะบางและข้อจำกัดของร่างกายกับการดูแลตนเองในเชิงแนวคิด จึงต้องยอมรับว่า framing “care จาก embodiment” มีผู้เสนอแล้ว รายงานนี้ไม่พบผลทดลองการล้มพร้อมร่างกายแตกหักในบทความนี้. [บทความ](https://arxiv.org/html/2510.07117v1)

## 5. ช่องว่างที่เหลือและถ้อยคำที่ควรใช้

| ข้ออ้างที่อาจใช้ตั้งโครงการ | ผลจากหลักฐาน |
|---|---|
| AI ยังจัดลำดับความเสียหายแต่ละส่วนไม่ได้ | กว้างเกินไป; SafeFall กำหนดลำดับผ่านน้ำหนักได้แล้ว |
| ทุกงานแยก predictor / balance / fall | ไม่จริง; มี unified control หลายแบบ |
| ไม่มี single policy เปลี่ยนจากสมดุลเป็นล้มเอง | ไม่แข็งแรง; งานมีนาคม 2026 ใกล้โดยตรง |
| ไม่มีการเทียบ multi กับ single | ไม่จริงในความหมายกว้าง; ballbot เทียบแล้ว |
| FEM + RL เพื่อรักษาของไม่ให้เสียเป็นของใหม่ | ไม่จริง; มี tool lifespan และ soft robot RL |
| ความเปราะบางทำให้เกิด self-preservation เป็นหลักการใหม่ | ไม่ใช่; มี intrinsic motivation และทฤษฎีที่เกี่ยวข้อง |
| ความเสียหายที่ทำให้ทำภารกิจต่อไม่ได้ สอน anticipatory protective falling ได้เองแค่ไหน | ยังมีเหตุผลให้ทดสอบ; ไม่พบการทดสอบตรงครบเงื่อนไขในชุดงานที่ตรวจ |

ข้อเสนอชื่อคำถามวิจัยที่เหมาะสม:

> **ความเสียหายทางกายที่คงอยู่เพียงพอหรือไม่ให้ policy เดียวเรียนรู้การล้มเพื่อรักษาความสามารถ โดยใช้รางวัลภารกิจต่อเนื่องเพียงอย่างเดียว?**

ชื่อภาษาอังกฤษชั่วคราว:

> **Can Persistent Functional Damage Induce Protective Falling under Task-Only Reinforcement Learning?**

คำว่า task-only ควรประกาศอย่างเข้มงวด หากภายหลังต้องเพิ่มรางวัลแรงกระแทก อายุยืน หรือท่าป้องกัน ต้องแยกเป็นเงื่อนไขทดลองอีกชุด ไม่เปลี่ยนนิยามย้อนหลัง

ความใหม่ที่มีประโยชน์ไม่ใช่แค่รวม “policy เดียว + FEM + damage + long horizon” ให้ไม่เหมือนชื่อบทความอื่น แต่เป็น **การทดสอบเชิงเหตุว่า feedback ทางกายชนิดใดทำให้พฤติกรรมเปลี่ยน** และหาขอบเขตที่วิธีนี้สู้ explicit safety objective ได้หรือไม่ได้

## 6. FEM รันไหวหรือไม่ และจำเป็นแค่ไหน

คำตอบคือ FEM ใช้กับ RL ได้ในบางระดับ แต่ไม่มีหลักฐานพอจะบอกว่า FEM เนื้อเยื่อ–กระดูกทั้งร่างกายพร้อมแตกหักจะฝึกโจทย์นี้ได้คุ้มบนเครื่องที่มีอยู่ การทำ simulation หนึ่งครั้งได้กับการสร้างประสบการณ์ RL จำนวนมากเป็นคนละปัญหา

**Soft Robots Learn to Crawl — RSS 2022** ใช้ finite element simulation ร่วมกับ model order reduction และ hyper-reduction เพื่อร่วมเรียนรู้โครงสร้างกับการควบคุม และทดสอบหุ่นจริง นี่เป็นตัวอย่างตรงว่า FEM + RL ทำได้เมื่อเลือก representation ให้เหมาะ แต่ไม่ได้พิสูจน์ความแม่นของการแตกหักในร่างกายมนุษย์. [บทความ](https://arxiv.org/pdf/2202.04575), [เว็บไซต์ผู้เขียน](https://sites.google.com/ttic.edu/evolving-soft-robots)

**SofaGym** มี environment สำหรับ RL บน SOFA และเป็นจุดเริ่มศึกษาการเชื่อม FEM กับการควบคุม อย่างไรก็ตาม ต้องวัด environment ที่เลือกจริง ไม่อนุมานว่า soft body ทุกขนาดจะให้ throughput เดียวกัน. [repository ผู้พัฒนา](https://github.com/SofaDefrost/SofaGym), [บทความ](https://doi.org/10.1089/soro.2021.0123)

**Sim-to-Real Gentle Manipulation of Deformable and Fragile Objects — 2025** ใช้ MPM สำหรับวัตถุเปราะบางพร้อม stress penalty และ curriculum จากวัตถุแข็งไปวัตถุอ่อน เป็นหลักฐานอีกแนวทาง แต่ MPM ไม่ใช่ FEM และงานนี้ยังใช้ objective ลด stress โดยตรง. [บทความ](https://arxiv.org/html/2510.25405v1)

ตัวอย่างต้นทุน FEM ทั้งร่างกายในงาน **Development of a Computationally Efficient Full Human Body Finite Element Model — 2015** ระบุว่าโมเดลละเอียด M50-O ใช้ประมาณ 24 ชั่วโมงบน 48 CPUs สำหรับเหตุการณ์ sled 250 มิลลิวินาที รุ่นย่อ M50-OS เร็วกว่าแต่ผู้เขียนระบุว่าไม่ได้มีวัตถุประสงค์ทำนาย crash-induced injuries ตัวเลขนี้เป็น benchmark เก่าของ configuration เฉพาะ ใช้ชี้ trade-off เท่านั้น ห้ามนำไปประมาณเวลาเครื่องปัจจุบันโดยตรง. [บทความต้นฉบับ](https://www.tandfonline.com/doi/pdf/10.1080/15389588.2015.1021418)

แบบ musculoskeletal ที่มีข้อต่อและกล้ามเนื้อจำนวนมากก็ไม่เท่ากับ injury FEM: **Bipedal Balance Control with Whole-body Musculoskeletal Standing and Falling Simulations — 2025** ใช้ MuJoCo และกล้ามเนื้อแบบ Hill พร้อมการควบคุม MPPI/PD และตัวอย่างกล้ามเนื้ออ่อนแรงที่กำหนดไว้ เป็นคนละระดับกับการคำนวณเนื้อเยื่อฉีกหรือกระดูกหักจากแรงกระแทก. [บทความ](https://arxiv.org/html/2506.09383v1)

### ระดับ fidelity ที่เหมาะกับการตัดสินใจ

| ระดับ | สิ่งที่จำลอง | ใช้ตอบคำถามใด | ข้อเสนอ |
|---|---|---|---|
| 1 | rigid-body contacts + แบบจำลองเสียความสามารถที่ตรวจสอบได้ | กลไก future task loss เพียงพอให้เกิดการป้องกันตัวไหม | เริ่มตรงนี้ |
| 2 | ข้อต่อ/ส่วนเปราะบางเฉพาะจุด + local stress/damage model | ผลยังอยู่ไหมเมื่อกลไกเสียหายละเอียดขึ้น | ทำหลัง pilot |
| 3 | FEM offline หรือ surrogate ที่สอบเทียบจาก FEM | ลำดับท่าที่ดูปลอดภัยยังถูกต้องภายใต้โมเดลละเอียดไหม | ใช้ตรวจ trajectory ที่คัดไว้ |
| 4 | whole-body nonlinear tissue/fracture FEM ในทุก rollout | ข้ออ้างเชิงชีวกลศาสตร์ที่ละเอียดมาก | ยังไม่คุ้มเริ่ม |

การย่อแบบจำลองต้องเก็บสายเหตุที่สนใจไว้: **การกระทำ → โหลด → ความเสียหาย → การส่งแรง/การควบคุมที่เปลี่ยน → ผลภารกิจในอนาคต** หากเก็บเพียงแรงสูงสุดแล้วบวกคะแนนลบ จะย้อนกลับไปเป็นโจทย์ที่งานเดิมทำ

FEM เองไม่ได้บอกว่าอะไร “สำคัญ” โดยอัตโนมัติ ผู้สร้างยังต้องระบุวัสดุ เงื่อนไขขอบ การแตกหัก และวิธีเชื่อมส่วนเสียกับหน้าที่ร่างกาย แบบ surrogate ที่ทาย stress ดีในสภาพปกติก็ยังต้องตรวจต่างหากเมื่อเกิดความเสียหายหรือ contact pattern ใหม่

## 7. แบบทดลองขั้นต่ำที่คุ้มทำ

ส่วนนี้เป็นข้อเสนอออกแบบการทดลองจากการสังเคราะห์ ไม่ใช่ผลทดลองที่มีอยู่แล้ว

ให้สถานะกายภาพเป็น x และสถานะความเสียหายเป็น d:

```text
d[t+1] = DamageUpdate(d[t], loads[t], material_parameters)
x[t+1] = PhysicsStep(x[t], action[t], d[t])
reward[t] = TaskReward(x[t], action[t], task[t])
```

ในเงื่อนไขหลัก reward ไม่อ่าน d โดยตรง แต่ d เปลี่ยนสิ่งที่ agent ทำได้จริง การรับรู้ความเสียหายผ่าน observation ทำได้และควรประกาศแยกจากการให้คะแนนความเสียหาย ถ้า state นี้ซ่อนอยู่ อาจใช้ประวัติการเคลื่อนไหวหรือ recurrent policy เพื่อไม่ให้ปัญหากลายเป็นเดา damage จากข้อมูลที่ไม่พอ

เริ่มจากร่างกายขนาดเล็กที่มีแขน ขา และลำตัว พร้อมทางเลือกสัมผัสพื้นหลายแบบ หากเริ่ม 2D ต้องสรุปผลเฉพาะระนาบนั้นก่อน ไม่อ้างการม้วนตัวทุกทิศทางหรือการบาดเจ็บของมนุษย์

### 7.1 แยกกลไกด้วยสี่เงื่อนไขก่อนเทียบสถาปัตยกรรม

| เงื่อนไขฝึก | damage ลดความสามารถจริง | มีโทษ damage ตรง | หน้าที่ในการทดลอง |
|---|---:|---:|---|
| A | ไม่; บันทึก counterfactual damage อย่างเดียว | ไม่ | ภารกิจอย่างเดียวเมื่อร่างกายไม่เสื่อม |
| B | ใช่ | ไม่ | สมมติฐานหลักของโครงการ |
| C | ไม่; บันทึก damage | ใช่ | ประโยชน์จาก explicit penalty |
| D | ใช่ | ใช่ | ทั้งผลทางกายและสัญญาณชี้นำ |

ทุกชุดใช้ single policy ก่อน คุม morphology, observations, actions, tasks และงบปรับพารามิเตอร์ให้เทียบได้ ประเมินทั้งสี่ใน environment ทดสอบที่ damage ส่งผลจริงเหมือนกัน การปิด dynamics ระหว่างฝึกเป็น intervention ที่ตั้งใจ ไม่ใช่ข้ออ้างว่าทั้งสี่ฝึกด้วย dynamics เดียวกัน

ผล B เทียบ A ช่วยตอบว่าการเผชิญผลเสียทางกายขณะฝึกทำให้พฤติกรรมเปลี่ยนหรือไม่ ผล B เทียบ D ช่วยแยกว่าการเพิ่ม penalty ช่วยประสิทธิภาพการเรียนรู้หรือเปลี่ยน trade-off แค่ไหน เมื่อกลไกนี้มีหลักฐานแล้วค่อยลงทุนเปรียบเทียบ single policy กับระบบ explicit switching โดยใช้ objective และ body model เดียวกัน

### 7.2 ต้องมี “อนาคตหลังล้ม” ที่มีคุณค่า

อย่าจบ episode ทุกครั้งที่ลำตัวแตะพื้น และอย่าคืนร่างกายสมบูรณ์ให้ทันทีหลังล้ม ต้องให้มีช่วงใช้ร่างกายหลังเหตุการณ์ เช่น เดินไปเป้าหมายและใช้แขนขยับของ เพื่อให้การรักษาแขน/ขาเปลี่ยนผลภารกิจจริง

ใช้เวลาประเมินคงที่ร่วมกัน หากเสียหน้าที่ทั้งหมดให้สถานะนั้นมีผลตามกติกาภารกิจต่อไป ไม่แอบให้โบนัสหรือลบคะแนน “ตาย” ในเงื่อนไข task-only โดยไม่ประกาศ ต้องตรวจ reward sign และ reset ด้วย เพราะการออกจาก episode อาจกลายเป็นทางหนี cost

horizon กับ discount เป็นส่วนของสมมติฐาน ตัวอย่างคำนวณที่ control 50 Hz: รางวัลหลัง 10 วินาทีถูกคูณประมาณ 0.0066 เมื่อ gamma = 0.99 แต่ประมาณ 0.606 เมื่อ gamma = 0.999 การบอกว่าใช้ episode ยาวจึงไม่ได้แปลว่า optimizer ให้ความสำคัญกับอนาคตนั้นมากพอ ตัวเลขนี้เป็นการคำนวณจาก gamma ยกกำลัง 500 ไม่ใช่ค่าที่แนะนำให้ใช้โดยไม่ทดลอง

### 7.3 การทดลองเรื่อง “จัดอันดับความเจ็บ” ที่แยกจากการตั้งน้ำหนัก

ใช้ร่างกายและวัสดุเดิม แต่สลับภารกิจอนาคต: ชุดหนึ่งต้องเดินต่อมาก อีกชุดต้องใช้แขนทำงานหลังล้ม ดูว่าการยอมรับแรงของแขน ขา และลำตัวเปลี่ยนตามความต้องการงานหรือไม่

หากเปลี่ยน priority โดยไม่เปลี่ยนค่าน้ำหนัก damage จะสนับสนุนว่า policy เรียนรู้คุณค่าเชิงหน้าที่ หากรักษาส่วนเดิมตลอด อาจมาจากข้อจำกัดเชิงกล รูปทรง หรือการค้นพบ local optimum ต้องมี trajectory และการทดลองแทรกแซงเพื่อแยก ไม่ตีความจากคลิปอย่างเดียว

การเรียนรู้เช่นนี้อาจยอมเสียส่วนที่ไม่จำเป็นต่อภารกิจ ซึ่งสอดคล้องกับ task-only objective แต่ไม่ใช่การรักษาสุขภาพทุกด้านของมนุษย์

## 8. วัดอะไรจึงจะตอบคำถามได้

ตัวชี้วัดหลักควรเป็น **ผลตอบแทนภารกิจที่ไม่รวม safety shaping** ตลอด horizon ทดสอบ พร้อมความสามารถที่เหลือหลังล้ม แสดงผลรายส่วนเพื่อไม่ซ่อนการย้ายความเสียหายจากส่วนหนึ่งไปอีกส่วนหนึ่งด้วยค่าเฉลี่ยรวม

รายงานอย่างน้อย:

1. จำนวนหรือคุณภาพภารกิจที่ทำต่อสำเร็จหลัง disturbance
2. การสูญเสียแรงขับ ช่วงการเคลื่อนไหว หรือความสามารถเฉพาะส่วน
3. อัตราสูญเสียหน้าที่รุนแรง การกู้สมดุลสำเร็จ และการลุกกลับมาทำงาน
4. contact force/impulse เป็นข้อมูลประกอบ; ไม่เท่ากับ injury โดยอัตโนมัติ
5. ความแปรปรวนข้าม training seeds และผลบน disturbance ที่ไม่ใช้ปรับโมเดล

ประเมินบนชุดแรงรบกวนเดียวกันทุก policy และรายงานรวมทุกกรณี อย่าเลือกเฉพาะเหตุการณ์ที่แต่ละ policy “ล้มแล้ว” เพราะ policy หนึ่งอาจหลีกเลี่ยงการล้มได้ในสถานการณ์ที่อีก policy ล้ม การคัดคนละกลุ่มจะทำให้สรุปความปลอดภัยผิด

### FAR และ lead time ยังใช้ได้ แต่ต้องนิยามใหม่อย่างระวัง

ระบบ classifier มี alarm timestamp ชัดเจน ส่วน single policy ไม่มี “คำสั่งสลับ” โดยธรรมชาติ การเคลื่อนไหวอาจค่อย ๆ เปลี่ยนจากแก้สมดุลเป็นรองรับแรง ไม่จำเป็นต้องมีขอบเขตคม

หากต้องวัด protective-onset ให้กำหนดตัวชี้วัดพฤติกรรมหลังการทดลองและทดสอบความไวต่อ threshold หลายค่า โดยไม่ส่ง classifier นี้กลับไปควบคุม agent มิฉะนั้นจะเอาสวิตช์ที่ต้องการเลี่ยงกลับมาใส่ในระบบ

ไม่ควรนับทุกการย่อเข่าหรือใช้แขนเป็น false alarm เพราะบางการเคลื่อนไหวช่วยกู้สมดุลด้วยได้ ให้รายงาน task cost ของการป้องกันใน disturbance ที่ recoverable และกำหนด recoverability เทียบกับ controller/reference search ที่ระบุชัด วิธีนี้สืบต่อข้อจำกัดของการทำนายที่สัมพันธ์กับ controller ในงาน 2011. [Learning to Predict Humanoid Fall](https://www.cse.iitb.ac.in/~shivaram/papers/kg_ijhr_2011.pdf)

**ข้อเสนอ:** ใช้ retained function และ future task return เป็นผลหลัก ส่วน FAR–lead-time เป็นผลเสริมเมื่อมีนิยามที่เทียบกันได้ ไม่วางข้อเสนอวิจัยทั้งหมดไว้บนการหาจุด switch ที่อาจไม่มีจริง

## 9. หลักฐานทางฟิสิกส์และต้นทุนที่ต้องผ่าน

ก่อนฝึกยาว ต้องมีกรณีทดสอบที่แสดงว่าโหลดทำให้เกิดผลที่ตั้งใจจริง และเส้นทางปลอดภัยมีอยู่ในร่างกายนี้ การที่ RL ล้มเหลวทั้งที่ไม่มีทางรอดเชิงกลไม่ตอบอะไรเกี่ยวกับการเรียนรู้

ตรวจขั้นต่ำ:

- ลด timestep หรือเปลี่ยน contact stiffness แล้วลำดับความรุนแรงของท่าหลักไม่พลิกอย่างไร้เหตุผล
- นิยาม damage accumulation ใช้หน่วยเวลา/โหลดถูกต้อง ไม่โตเพราะเพิ่มจำนวน simulation steps
- การสูญเสีย actuator/ข้อต่อส่งผลต่อ force transmission และ performance จริง
- ไม่มีพลังงานงอกหรือการพุ่งจาก contact solver ที่ agent ใช้ทำคะแนน
- ความเสียหายที่ไม่รีเซ็ตคงอยู่ตลอดช่วงภารกิจตามที่ประกาศ
- ท่าที่ดูดีผ่านโมเดลหรือพารามิเตอร์ที่ไม่ใช้ฝึกด้วย

ตัวเลขฝึกจากวรรณกรรมมีช่วงกว้างมาก: FRASA รายงาน 13–37 นาทีบน i9-12900, RTX 3060, RAM 64 GB สำหรับโจทย์ที่ลดมิติแล้ว; SafeFall รายงานรวม 280 GPU-hours; งาน arm-assisted ใช้ 3.93 พันล้าน environment steps ในการเปรียบเทียบบางชุด ตัวเลขต่างโจทย์นี้ไม่ใช่ benchmark แข่งกัน และห้ามนำมาคาดเวลาโครงการใหม่ตรง ๆ. [FRASA §V-C](https://arxiv.org/html/2410.08655v1), [SafeFall training](https://arxiv.org/html/2511.18509v1), [Arm-assisted evaluation](https://arxiv.org/html/2303.05486v1)

ยังไม่มี throughput benchmark ของ RL Fall ในรายงานนี้ จึงไม่กำหนดจำนวนวันหรือรับรองว่า VRAM ขนาดใดพอสำหรับ full-body FEM การประเมินงบควรเริ่มจาก environment เล็ก วัด aggregate control steps ต่อวินาที, physics substeps, memory และเวลา optimizer update แล้วรวมจำนวน seeds/conditions ที่ต้องรันจริง

## 10. เกณฑ์เดินหน้าหรือหยุด

| ประตูตัดสินใจ | หลักฐานที่ต้องมี | ถ้าไม่ผ่าน |
|---|---|---|
| ความถูกต้องของ environment | damage เปลี่ยนหน้าที่จริง; มีทางเลือกตกที่ผลต่างกัน | แก้ environment ก่อนโทษ RL |
| การเรียนรู้ภารกิจ | policy ทำงานพื้นฐานได้ทั้งก่อนและหลังความเสียหายบางระดับ | ลดขนาดโจทย์/แก้การรับรู้และ horizon |
| กลไกหลัก | B ให้ future task return/retained function ดีกว่า A อย่างสม่ำเสมอข้าม seeds | ตรวจ exploration/credit assignment; อย่าเพิ่ม penalty แล้วอ้างผลเดิม |
| คุณค่าเพิ่ม | priority เปลี่ยนตาม future task หรือพบขอบเขตที่ B เทียบ D ได้ | ถ้ามีเพียงท่าล้มสวยขึ้น ความใหม่ยังอ่อน |
| ความทนต่อโมเดล | ผลคงอยู่เมื่อเปลี่ยนโหลด วัสดุ contact และโมเดลประเมิน | ยังไม่ควรเพิ่มข้ออ้างเชิงชีวกลศาสตร์ |
| ขยายขนาด | pilot ให้ข้อค้นพบที่ชัดและงบฝึกวัดแล้วรับได้ | เลื่อน 3D/FEM รายละเอียดสูงออกไป |

ไม่มีเกณฑ์เปอร์เซ็นต์สำเร็จที่มีฐานข้อมูลพอจะกำหนดล่วงหน้าในตอนนี้ ควรกำหนด effect size ที่มีความหมายและงบทดลองหลังได้ variance จาก pilot โดยแยก pilot ออกจากชุดทดสอบสุดท้าย

หาก B ไม่สำเร็จแต่ D สำเร็จ ผลลบอาจยังมีคุณค่าเมื่อแสดงได้ว่าเพราะ horizon, observability หรือความยากของ credit assignment และทำซ้ำได้ แต่ไม่ควรกล่าวว่าได้พิสูจน์ว่า task-only self-protection “เป็นไปไม่ได้” จากการฝึกอัลกอริทึมเดียว

## 11. ขอบเขตที่คุ้มลงทุน

| แนวทำโครงการ | ประเมินความคุ้มจากหลักฐาน |
|---|---|
| ทำ demo humanoid ล้มปลอดภัยด้วย RL | ดีต่อการเรียนรู้ แต่ความใหม่ทางวิจัยต่ำ |
| เทียบ single กับ explicit switch อย่างเดียว | มีโอกาสทำ benchmark ที่ดี แต่ต้องยอมรับ prior art และคุมปัจจัยอย่างเข้ม |
| พิสูจน์บทบาทของ damage → loss of function → future task value | น่าทำ pilot มากที่สุด; มีคำถามเชิงเหตุที่แยกจากงานใกล้ |
| ทำ FEM ร่างกายมนุษย์ทั้งหมดก่อน | ต้นทุนสูงและยังไม่จำเป็นต่อการตอบคำถามหลัก |
| อ้างสัญชาตญาณหรือความเจ็บแบบมนุษย์ | หลักฐานที่เสนอไม่พอรองรับ |

**ข้อเสนอการตัดสินใจ:** ลงมือเฉพาะ pilot ที่แยกสี่เงื่อนไขและมีงานต่อหลังล้มก่อน หากได้หลักฐานว่าความเสียหายทางกายเปลี่ยนการป้องกันตัวตามคุณค่าของภารกิจ จึงขยายเป็น 3D เทียบสถาปัตยกรรม และใช้ FEM ตรวจ trajectory เฉพาะส่วน การค้นครั้งนี้สนับสนุนการลงทุนเพื่อพิสูจน์สมมติฐานดังกล่าว แต่ยังไม่สนับสนุนการลงทุนสร้างร่างกายละเอียดทั้งหมด

## 12. ข้อจำกัดของข้อสรุป

- งานจำนวนหนึ่งเป็น preprint; รายงานผลตามผู้เขียน ไม่ถือว่าทุกงานผ่าน peer review หรือถูกทำซ้ำแล้ว
- ตรวจวิธีและสมการของงานใกล้เคียง แต่ไม่ได้รัน code หรือ benchmark ของทุกงาน

- รายงานนี้เสนอขอบเขตวิจัย ไม่ใช่แบบจำลองการบาดเจ็บที่ผ่านการรับรองหรือคำแนะนำท่าล้มสำหรับคน
